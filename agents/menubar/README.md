# Patched Updater — menu bar app

SwiftUI menu bar agent for each client Mac. Displays the protection status the
privileged daemon publishes. This is an assurance-only release: app
installation and removal are unavailable. PAT-1619 removed the menu bar app's
own Deploy window and its Self Service hand-offs; PAT-1618 removed the
standalone PatchedSelfService application itself. The agent no longer writes
an update/deploy trigger. The trigger types it still writes are `os_defer`
(the OS-update blocking prompt's Defer button) and, since PAT-1623,
`removal_defer` (the removal notify/defer prompt's Defer button — see
"Removal notify/defer surface (PAT-1623)" below). Neither actuates anything
from the menu bar: both are markers the privileged daemon reads and acts on.

## Building

`menubar/PatchedUpdater.xcodeproj` is gitignored — it is generated from `project.yml`.

```sh
cd menubar
xcodegen generate          # regenerate .xcodeproj from project.yml
```

Then build:

```sh
xcodebuild -project PatchedUpdater.xcodeproj \
           -scheme PatchedUpdater \
           -configuration Debug \
           build \
           CODE_SIGN_IDENTITY="" CODE_SIGNING_REQUIRED=NO CODE_SIGNING_ALLOWED=NO
```

Or open `menubar/PatchedUpdater.xcodeproj` in Xcode 16+ and hit ⌘B.

**Requirements:** macOS 13+, Xcode 16+ (Swift 5.9+). No third-party Swift dependencies.

## Local development

Point the app at a writable dev directory to run without the daemon installed:

```sh
mkdir -p ~/patched-dev
cp contracts/update-status.sample.json ~/patched-dev/update-status.json
PATCHED_UPDATER_DIR=~/patched-dev open build/PatchedUpdater.app
```

The `PATCHED_UPDATER_DIR` override is consumed by `StatusStore.init()`. The
agent does not create the trigger directory (`triggers/`) for a deploy; its
remaining trigger writes are `os_defer` (OS-update blocking prompt) and
`removal_defer` (PAT-1623 removal notify/defer prompt).

**Testing states:** edit `update-status.json` and write a replacement atomically
to exercise the directory-watch hot-reload:

```sh
# Replace status file atomically (simulates daemon write)
cp new-status.json ~/patched-dev/update-status.json.tmp
mv ~/patched-dev/update-status.json.tmp ~/patched-dev/update-status.json
```

## How it works

1. The daemon (`engine/patched-update.sh`, `com.patched.update` LaunchDaemon)
   writes `/Library/Application Support/Patched/update-status.json` atomically
   after every run.
2. `StatusStore` opens the directory with `O_EVTONLY` and watches for
   `.write/.rename/.delete` events so the UI updates live even on atomic renames.
   A 20-second poll backstops missed events.
3. PAT-1619 removed the menu bar app's own "Deploy an app…" window, which used
   to write `*.trigger` JSON files for the daemon's `WatchPaths` to pick up.
   The agent's remaining trigger writes are `os_defer`, dropped by
   `StatusStore.requestOsDefer()` when the OS-update blocking prompt's Defer
   button is used, and (PAT-1623) `removal_defer`, dropped by
   `StatusStore.requestRemovalDefer(pending:)` from the removal notify/defer
   prompt's Defer button.

## Removal notify/defer surface (PAT-1623)

PAT-1598 commits to never taking a running application with unsaved work
during removal: defer, notify the user, retry, and report `deferred` rather
than `failed`. The backend (`endpoint/patched-uninstall.sh`, PAT-376) already
detects a running removal target and writes
`removals[].outcome == "deferred_app_running"` to
`uninstall-status.json` — this section is what tells the person at the
keyboard, since Self Service (which used to own that interaction) was deleted
under PAT-1617.

1. `StatusStore` reads `uninstall-status.json` (same base dir, same
   file-watch/poll infrastructure as `update-status.json`) via
   `UninstallStatus.swift` and tracks which `entry_id`s are currently
   `deferred_app_running`.
2. A *newly*-deferred app requests a presentation attempt
   (`removalPromptAttempt`); an app that was already known-deferred on the
   previous read does not — re-reading the same unchanged file every 20
   seconds must not re-notify every cycle.
3. `attemptRemovalPromptPresentation` is the one call site, gated on:
   - **managed tier only, fail closed** (`applyRemovalTierGate`) — inert on
     every other tier;
   - **"queue, do not stack"** — it refuses to present whenever
     `shouldShowBlockingPrompt` (the OS-update prompt) is also true, since the
     OS update has a real deadline and removal costs nothing to wait;
   - the same `PromptPresentationGovernor`/`InterruptionGate` the OS-update
     prompt uses, via a second, independent governor instance
     (`surface: "removal"`).
4. `RemovalPromptView` (via `RemovalPromptWindowController`) reuses the OS
   update's window shell (`PromptWindowShell`) but never shows a deadline, a
   deferrals-remaining count, or a disabled Defer button — `RemovalPromptPolicy`
   is a wholly separate policy object from `InterruptionPolicy` precisely so
   removal's "no terminal state, ever" guarantee can never be compromised by a
   value shared with the OS-update prompt's deadline semantics.
5. Defer writes a `removal_defer_<uuid>.trigger` marker (mirrors `os_defer`'s
   shape, distinct `type` so the two deferral budgets are never tallied
   together) and dismisses the local prompt only — it never touches the
   daemon's own automatic `DeferredAppRunning` retry, which already runs next
   cycle regardless.

## Status contract (PAT-45)

`UpdateStatus.AppEntry` carries:
- `verified_signer` — the codesign team ID that passed verification (`null` if
  not verified or not applicable).
- `failure_reason` — `missing_expected_signer | signature_untrusted | signer_mismatch`
  when `state == "verification_failed"`; `null` otherwise.
- `state == "unknown"` means the scan ran but version data is not yet available —
  rendered calmly as "Version pending", not as an error.

## Tier flag (PAT-279)

The app defaults to Tier 1 (`appTier = .tier1` in `PatchedUpdaterApp.swift`).
Tier 1 uses a static pixel-P menu bar icon with no badge. Tier 2 (delivered via
per-tenant config in PAT-279) will enable a Signal-orange attention badge. The
wiring point is marked with `// PAT-279` in the source.
