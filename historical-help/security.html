Security

Security architecture

Patched receives evidence from software running on customer endpoints. That makes the agent, ingestion API and tenant boundary the controls that matter most.

Collection boundary

The Patched agent collects inventory and assurance evidence. It does not expose an inbound command channel, provide remote control or act as the customer’s endpoint-management authority.

  • No screen sharing, device wipe, lock or arbitrary shell.
  • No proprietary installer repository or curated end-user app store.
  • Remediation remains in Intune, Jamf, patch-management or ticketing tools.

Authenticated inventory uploads

Both platform agents POST a versioned, platform-neutral inventory payload to api.patched.im over HTTPS. Every request carries tenant credentials and an HMAC-SHA256 signature over the exact payload bytes. Timestamp and nonce checks reject replay.

Absence requires authority. Missing or stale collection cannot prove software is absent, close a finding or prove a control healthy. Reports retain collection time and evidence scope.

Tenant and device identity

Tenant credentials determine the ingestion boundary. Device identity is derived from stable hardware identifiers and enrolment context. The service validates the tenant before accepting or associating a payload, and customer-facing access is scoped to the authenticated tenant.

Endpoint release trust

Code shipped to customer endpoints is a supply-chain gate. Agent releases are versioned, provenance-sensitive and subject to a full code and security review before the first customer release. Customers control the channel used to deploy and update the collector.

Legacy isolation

Legacy packaging, deployment and end-user app-store code is being quarantined from the retained collector. Security and compatibility work may be required to isolate it safely, but it is not an active capability or a reason to broaden agent authority.

Infrastructure boundary

Public endpoints use TLS and edge protection. Administrative access to Patched servers is private-network only, and the database is not exposed publicly. Encrypted backups and operational access controls are part of the platform boundary.

Report a vulnerability

Email hello@patched.im with “Security” in the subject. Include the affected component, observed behaviour and a safe reproduction where possible.
