Guide 01

Getting started

This guide covers the current path: provision a tenant, deploy the Windows or macOS collector, receive inventory and review the first configuration-assurance evidence.

The short version

We deploy a lightweight inventory agent to your endpoints. It collects a hardware, OS and application inventory plus a set of CIS Level 1 security signals, and sends them to api.patched.im over an authenticated, signed channel. We score every device against the CIS benchmark and turn it into a report and a live dashboard. No MDM is required to start. The agent installs in minutes and runs on its own.

Step 1: We provision your tenant

Each customer is a tenant. Enrolling a device starts with a single-use enrolment token, valid for around 24 hours, rather than a set of credentials you handle yourself. The agent redeems the token the first time it runs and obtains its own per-device credentials automatically. There's nothing for you to copy, store or type in.

Every token starts the same way: generated from the portal's Install tab. From there you either upload the artifact it produces to Intune as part of the rollout below, or run that same artifact directly on the device if you're installing without MDM. See using your Patched portal for a tour of the Install tab.

Step 2: Deploy the agent

There are two ways onto a device, depending on how it's managed.

Via Intune (recommended for managed estates)

The agent package is provided by Patched during onboarding and installed through Intune like any other managed app. Enrolment itself is self-serve: generate a single-use token from the portal's Install tab, then upload the macOS artifact it produces to Intune as a Platform Script that runs as root and writes the token to the device, or run the Windows artifact as an Intune Win32 app install command. Once it's assigned to a device group, enrolled endpoints pick it up automatically; there's nothing for the end user to do, and no Gatekeeper prompts.

Without MDM (direct install)

For endpoints that aren't in Intune (including a first pilot machine), an administrator generates a single-use enrolment token from the portal's Install tab and runs the matching artifact by hand: the macOS script, or the Windows msiexec command, each with the token already built in. The same agent, the same data; it simply installs a small background task to collect and upload on a schedule instead of being triggered by Intune.

Sign in to the portal at app.patched.im to generate a token and grab the artifact for your platform directly. See using your Patched portal for a tour of the Install tab and what else is in there.

No MDM is required to start. Intune, Jamf or another management platform can deploy the collector, but Patched does not require customers to replace or standardise their existing endpoint tools.

Step 3: First inventory & scan

On its first run the agent assembles a snapshot of the device: hardware identity, OS version, installed applications, pending updates, and the CIS compliance signals (FileVault, firewall, Gatekeeper, screen-lock, and so on). It queues the snapshot locally and uploads it; if the device is offline, the snapshot waits and retries automatically. Uploads run roughly every 15 minutes, so the dashboard stays close to real time.

On our side, each snapshot is scored against the CIS Level 1 benchmark. Within a few minutes of the first upload the device appears in your dashboard with a compliance result for every control.

Step 4: Read your report

You get the results two ways:

  • A live dashboard: your estate's real-time compliance and inventory freshness and configuration posture at a glance, per device and rolled up across the estate.
  • Scheduled compliance reports: a polished PDF on your cadence, suitable for handing to an auditor or a board. Two shapes: a per-device report listing every failing control and the observed value, and an executive summary that rolls the whole estate into KPIs and the top things to fix.

Each failing control comes with what was expected, what we observed, and how to fix it. For a walk-through of the report itself, see How to read your report; for a deeper explanation of how scoring works and what a passing control proves, see What "Compliant" means.

What you need from your side

  • A way to reach the endpoints: Intune for managed estates, or admin access for a direct install.
  • Outbound HTTPS to api.patched.im from the endpoints (the agent only ever makes outbound connections; nothing listens on the device).
  • If antivirus or EDR blocks the collector, retain the alert and review the exact binary and path with Patched before creating any narrow exception.
  • That's it. No inbound firewall changes, no server to run, no MDM to stand up.
