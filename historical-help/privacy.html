Guide 06

Data & privacy

What the agent collects and why, what it explicitly does not collect, where your data goes and how it's protected, and the legal framework it operates under. Written for IT administrators, legal, and compliance teams evaluating a Patched deployment.

What the agent collects

Every field collected maps to a reporting or compliance purpose. Nothing is collected speculatively.

Hardware identity

Make, model, serial number, and hardware UUID. Used to identify devices across sessions, associate data with the correct endpoint, and support device-lifecycle reporting (enrolment, suspension, offboarding).

Operating system

OS version, build, and security update status. Used for operating-system currency, configuration assurance and end-of-support reporting.

Installed applications

Application name, version, source, and install date for every app on the device. The basis for software inventory, identity normalisation, governance classification and new-software detection.

Compliance signals

The CIS Level 1 control readings: disk encryption status, firewall configuration, screen-lock settings, automatic update state, remote-access surfaces, local administrator account count, and the rest of the benchmark. See What "Compliant" means for the full list.

Security posture signals

Certificate inventory and expiry dates, browser extension inventory, EDR and security-tool presence, FileVault / BitLocker encryption posture. Used for certificate-expiry alerting, browser-extension policy, and EDR coverage reporting.

Usage metering (opt-in, off by default)

Last-opened timestamp and run count per application. Only collected when explicitly enabled in your signed agent configuration: aggregate counts only, no window titles or file paths.

What the agent does not collect

  • Document contents, message bodies, email, or calendar data
  • Browsing history, search queries, or web page contents
  • Keystrokes or clipboard contents
  • Screen captures
  • Camera or microphone data
  • Home directory file listings
  • Proxy credentials (redacted before any log upload)

The acceptable-use terms prohibit using Patched as employee-surveillance tooling. Controls that could touch user-specific data require explicit per-tenant opt-in with a recorded reason.

How data leaves the endpoint

Destination

All agent uploads go to api.patched.im over HTTPS (TLS 1.2 minimum), port 443. No other outbound destination is required for the retained collection path. Remediation tools may require their own destinations, but they are outside the Patched agent data flow.

Authentication on every request

Every request carries a bearer token and an HMAC-SHA256 signature computed over the exact payload bytes. A timestamp and single-use nonce are also required. Any request that fails these checks is rejected before data is stored: see Security architecture for detail.

Log uploads

Agent logs are uploaded only when explicitly requested by the platform (per-device or tenant-wide). Before upload, the agent automatically redacts home directory paths, proxy credentials, bearer tokens, and any string matching a key-like pattern. Log bundles are retained for 30 days.

Data residency and storage

Platform infrastructure is hosted in the EU (Finland and Germany) on Patched-operated infrastructure. Data is stored in a PostgreSQL database with encrypted nightly backups. Patched is built and run from the Isle of Man by Patched.im Ltd, company number 139269C. Patched operates under the IoM Data Protection Act 2018, which mirrors the UK GDPR.

Data retention

Inventory snapshots, posture data, and provenance records are retained on the platform. Specific retention schedules and deletion timelines are available on request: email us or raise it at a security review.

Controller and processor

You are the data controller; Patched acts as the data processor. We process device and posture data on your instruction, for the purposes you specify, under the legal basis of legitimate interest (GDPR Article 6(1)(f) / IoM DPA 2018).

Data Processing Agreement

A DPA is available and covers: scope of processing, sub-processor list, 72-hour breach notification to the controller, data subject rights support (access, erasure, and portability within 30 days of your written instruction), and the right to one audit per 12-month period with 30 days' notice.

Sub-processors

The sub-processor list (infrastructure provider, backup provider, and VirusTotal) is available on request and will be maintained in the DPA schedule.

Security review and questions

We expect IT and security teams to do due diligence before deploying software with elevated access to their estate. The exact permissions differ by platform and collector version and should be reviewed during onboarding.

For data-flow diagrams, the full egress table, retention schedules, sub-processor details, the Data Processing Agreement, or to arrange a formal security review, email hello@patched.im.
