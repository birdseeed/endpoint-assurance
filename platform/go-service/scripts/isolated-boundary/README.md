# Isolated tenant-boundary harness (PAT-2367)

Builds a disposable local copy of the three Patched services, seeds two synthetic tenants, and runs an access-control
matrix against it. Everything binds 127.0.0.1. Nothing talks to any patched.im host, any Tailscale host or Cloudflare.
Outbound requests to anything that is not loopback are sent to a dead local proxy and fail.

## Commands

Run from this directory. Python comes from the portal checkout's virtualenv (it has requests, PyJWT, cryptography and
Playwright); override with `IB_PORTAL_PYTHON`.

```sh
./ib up      # build, start Postgres, local issuer, platform, extractor, recording proxy, portal, staff console
./ib seed    # tenants' principals and synthetic data, through the platform's own routes (no SQL)
./ib run     # the matrix, boundaries A to G; `./ib run --only A,B` for a subset
./ib down    # stop everything and confirm nothing is listening on a harness port
./ib all     # up, seed, run, then down (down always runs)
```

Defaults can be changed with environment variables: `IB_SCRATCH` (all temporary files), `IB_REPOS` (parent of the portal
and dashboard checkouts), `IB_PORTAL_REPO`, `IB_DASHBOARD_REPO`, `IB_PG_BIN` (PostgreSQL 16 binaries). Go builds need
`DEVELOPER_DIR=/Library/Developer/CommandLineTools` on this machine; `ib` sets it.

## What it does

- Takes pinned copies of `origin/main` of the portal and the staff console with `git archive` into the scratch directory.
  The live checkouts are never run or modified.
- Builds the platform from this worktree. A build-time overlay (`testdata/overlay/`, a directory name the Go tooling ignores, so the repository build never compiles it) adds one file that trusts the harness's
  throwaway CA for outbound HTTPS, because the platform fetches Access signing keys over HTTPS. No product file changes.
- Starts its own Postgres 16 on a loopback TCP port, applies every migration, and connects the platform as a non-superuser.
- `idp.py` is the stand-in for Cloudflare Access: an HTTPS JWKS endpoint and a minter for Access-style tokens.
- `tap.py` records every request the staff console sends to the platform's internal API.
- `seed.py` creates admin, viewer, disabled and domain-fallback portal users for tenants A and B, signed inventory for three
  devices each, and one object of each kind (certificate, declaration, report, enrolment key, device list, schedule).
- `matrix.py` (A, B, C, D, G), `browser.py` (E, with Playwright) and `staff.py` (F) run the checks and write one JSON file.

## Generated at run time (nothing here is a secret)

RSA signing keys, a rogue key, a throwaway CA and leaf certificate, the Postgres passwords, the admin API token, the
console API key, the platform's signing seed and envelope key, and all tenant credentials are generated by `ib up` into
`$IB_SCRATCH`. They are random, never committed, and only valid for that run. Principals use `.example` addresses and
canary strings (`CANARY-A-...`, `CANARY-B-...`) so that leakage is detectable by search.

Results are written to `$IB_SCRATCH/results/matrix-results-<timestamp>.json`; compute its sha256 to cite it.

## Limits

This proves behaviour of the code and configuration it runs. It cannot prove Cloudflare Access policy, edge placement,
real identity-provider sessions, production configuration, nginx, ufw or production timers. See the results document.
